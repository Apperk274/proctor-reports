Light Theme

Players can now choose the colour theme in Settings: Dark, Light or Follow phone. Dark stays the default, so nobody sees a change until they pick. Every screen is below in Dark next to Light, captured in the game at 1080 × 2340.

13

screen types checked in Light, 29 frames each way, all eight schools' day heroes included.

4.5:1+

every text role and every tone used as type, on every light ground. Button labels too, at both ends of their gradient.

1 rebuild

for each theme change. The UI is built again from the new theme on the next frame, without an entrance animation and without leaving the screen.

0

changes to how Dark looks. Every new token keeps the dark theme's old value.

How it works

  • Stored in the player's settings file (proctor_settings.json) as Theme: Dark, Light or FollowPhone. The format is still version 1, because the key is only an addition. An old file has no Theme and loads as Dark. A value this build does not know falls back to Dark and keeps every other setting.
  • Light is a new shipped theme, GameTheme.ModernLight(). It changes colour only: type, spacing, corners, sizes and motion are inherited from Dark. It uses the same indigo family on cool off-whites. The colours chosen for a dark page (bright green, pale brass, sky blue) were near 2:1 on white, so all of them are darker here.
  • Follow phone asks Android for Configuration.uiMode's night bits. The answer is cached and asked again whenever the game comes back to the front, so a phone switched to dark mode in the quick-settings shade changes the game when the shade closes. The editor and other platforms have nothing to ask, so Follow phone shows Dark there.
  • Applied at boot, before the first screen is built, and live afterwards. When the theme changes, UiRoot.Rebuild builds every screen again and the router redraws them from game state on the same frame. Nothing is lost, because every screen draws from state. The chrome inset and how far the page was scrolled are carried across. Entrance animations are held for that frame, so the switch is one clean frame with no flash. The Store and Wardrobe are drawn again too, because the Store's redraw key now includes the theme.
  • Settings has a Theme row in Display and help, built from the existing segmented control. The Manual has no settings section, so it has no new line.

Fixed for every screen, through tokens. All of these keep Dark exactly as it was.

  • The faint rank line. The hero's scrim is now a theme decision (HeroScrimReach, HeroScrimStrength, HeroScrimSolid). Dark keeps its single ramp. Light lays a solid ground under the whole text block and ramps above it, and its accents are dark enough to read on that ground (5.2:1 or better). The cost is that less of the daytime building shows behind the words than in Dark.
  • Disabled buttons fade toward the page. On a light page that leaves a pale tint, and their white labels read at about 2:1. Light now names a DisabledInk (slate) for them. Dark leaves it clear and keeps the old ink.
  • Full-screen card pages (results, events, the brief, the title) multiplied the dark theme's cool tint into the light page and turned it periwinkle. That tint is now ScrimTopTint.
  • The drawn shop tiles' cache is cleared on a theme change, and the strip of camera background outside the safe area follows a theme change while a screen covers the room.

For the Store and Wardrobe session

These are in code this pass did not touch (StoreScreen). No token fix in Ui or GameTheme could reach them without changing Dark.

  • The not-owned veil washes the tile art out in Light. StoreScreen.NotOwnedVeil lays Surface at 62% over a render you do not own. On a dark card that dims the art. On a white card it bleaches it nearly to nothing: the Phone Detector, the pills, the hats and the glasses are hard to make out. See Store, Wardrobe and the grid. A suggestion: give the veil its own role, or a lower strength in a light theme (for example a role that is Surface at 62% in Dark and around 35% in Light), so a light theme can dim without bleaching.
  • The three things you asked me to check. The Store and Wardrobe are rebuilt after a theme change, because the router's store key now carries GameTheme.Revision; that edit is in HudRouter, not StoreScreen. SupervisorPreviewStage takes its background from RaisedTop (a token), passed in from StoreScreen, and it matches its card in both themes. The room's colours were checked in a room started in Light: the phone-detector disc reads Primary each frame, the unwell haze keeps the dark theme's value on purpose (it is the room's own dark, and the room does not follow the theme), and the floor row numbers come from the floor colour. All three look right.
